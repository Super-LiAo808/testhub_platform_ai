## 一、项目概览

TestHub 是 AI 驱动的全栈测试管理平台，技术栈为 **Django 4.2 + Vue 3**。

| 维度 | 说明 |
|------|------|
| 后端 | Django 4.2、DRF、MySQL 8、JWT、Celery（可选）、Channels/Daphne |
| 前端 | Vue 3、Vite、Element Plus、Pinia、vue-i18n |
| 自动化 | Selenium / Playwright / browser-use；APP：Airtest + scrcpy 录制 |
| 文档入口 | 仓库 `README.md`；详细专题见 `docs/` |

## 三、核心能力速览

### AI

- 需求文档解析（PDF/Word/TXT）、用例生成
- Dify 助手；多模型（DeepSeek / 通义 / 硅基流动 / OpenAI 兼容等）

- Selenium / Playwright 双引擎
- 元素库、页面分组、POM、定时任务
- **Web 操作录制** → TestCase
- **页面 URL 异步扫描入库**（Playwright + 并发限制 + SSRF）

- Airtest 回放（图片 / 坐标 / 区域）
- 设备管理、组件包、UI Flow
- **scrcpy H.264 实时投屏录制**；失败回退截屏；中文输入按需 Appium（不抢前台）
- 执行进度 WebSocket（需 Daphne + Redis≥5）

### 其他

- API 测试、用例评审、数据工厂、JWT 双 Token、统一配置中心、i18n（中/英/日/韩）

## 四、录制与页面扫描

### 4.1 Web 操作录制

| 项 | 说明 |
|----|------|
| 入口 | `/ui-automation/recording` |
| 引擎 | Playwright Chromium（headed） |
| 产物 | `UIActionTrace` → 可编译 TestCase；密码等敏感输入脱敏 |
| 依赖 | HTTP 即可；**Daphne 下同样可用**（不依赖 WS） |

### 4.2 APP 操作录制 / 投屏

| 项 | 说明 |
|----|------|
| 入口 | `/app-automation/recording` |
| 镜像 | 优先 scrcpy → 前端 WebCodecs；回退截屏 |
| 控制 | 点击/滑动 ADB；复杂输入按需 Appium |
| 产物 | 图片元素 + `ui_flow` → AppTestCase |
| 运行 | **必须 Daphne + Redis≥5**；ADB；可选 Appium、`tools/scrcpy` |

相关环境变量：

```env
REDIS_URL=redis://127.0.0.1:6379/0
SCRCPY_MAX_SIZE=1280
SCRCPY_BIT_RATE=2M
# CHANNELS_REQUIRE_REDIS=True   # 生产建议
```

### 4.3 UI 页面元素扫描（异步任务）

流程：

1. `POST /api/ui-automation/elements/scan-page/` → `202` + `job_id`
2. 后台线程执行 Playwright 扫描并入库
3. `GET /api/ui-automation/elements/scan-jobs/{id}/` 轮询
4. `discovery_source=page_scan`，写入页面分组

服务端策略：

- 强制无头 Chromium
- 全局并发（默认 2，`UI_SCAN_MAX_CONCURRENT`）
- SSRF：拒绝 localhost / 私网 / 元数据
- 同项目排队任务上限
- 模型：`PageElementScanJob`（migration `0006`）

## 五、单机部署：全功能可用且避免服务冲突

### 5.1 原则

**一台服务器只起一个 Django/ASGI 入口（Daphne），不要同时再起 `runserver`。**

Web 录制与 APP 投屏：

| 资源 | Web 录制 | APP 投屏 | 结论 |
|------|----------|----------|------|
| HTTP | ✅ | ✅ | 共用 Daphne |
| WebSocket | 不需要 | ✅ 必需 | 必须 Daphne |
| 端口 8000 | 占用 | 占用 | **只能一个进程监听** |
| Playwright | ✅ | — | 独立进程 |
| scrcpy 端口 | — | 动态 | 不与 8000 冲突 |
| Appium 4723 | — | 按需 | 与 8000 无关 |
| Redis | 可选 | ≥5 推荐 | 共用 |

### 5.2 推荐进程

| 进程 | 作用 |
|------|------|
| Nginx | HTTPS、静态前端、反代 `/api` `/ws` |
| **Daphne :8000** | 全站 HTTP + WebSocket |
| MySQL 8 | 业务库 |
| Redis ≥5 | Channels + Celery |
| Celery worker | APP 等异步任务 |
| `run_all_scheduled_tasks` | API/UI 定时 |
| Appium（可选常驻） | APP 录制辅助 |

### 5.3 Nginx WebSocket（投屏关键）

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:8000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
}
location /ws/ {
    proxy_pass http://127.0.0.1:8000;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 86400;
}
location / {
    root /path/to/frontend/dist;
    try_files $uri $uri/ /index.html;
}
location /media/ {
    alias /path/to/testhub/media/;
}
```

### 5.4 生产环境变量要点

```env
DEBUG=False
SECRET_KEY=强随机
ALLOWED_HOSTS=域名
CORS_ALLOWED_ORIGINS=https://前端域名
CSRF_TRUSTED_ORIGINS=https://前端域名
REDIS_URL=redis://127.0.0.1:6379/0
CHANNELS_REQUIRE_REDIS=True
UI_SCAN_MAX_CONCURRENT=2
```

### 5.5 上线检查清单

1. 仅一个 Daphne，无 runserver 抢端口  
2. Redis 版本 ≥5，无 InMemory 静默降级  
3. Nginx `/ws/` 已 Upgrade  
4. `migrate` + `init_locator_strategies`（+ 可选 `load_component_pack`）  
5. 本机：Playwright Chromium、ADB、（录制）Appium、（可选）scrcpy  
6. 验证：Web 录制能弹 Chromium；APP 录制出现「投屏 WS·H264」

## 六、快速开始（开发）

```bash
# 后端
python -m venv venv
# Windows: .\venv\Scripts\Activate.ps1
pip install -r requirements.txt
cp .env.example .env   # 配 DB / REDIS
python manage.py migrate
python manage.py createsuperuser
python manage.py init_locator_strategies

# 推荐（含 WebSocket）
daphne -b 0.0.0.0 -p 8000 backend.asgi:application

# 前端
cd frontend && npm install && npm run dev
```

|------|------|

| API | http://localhost:8000 |
| Swagger | http://localhost:8000/api/docs/ |

```bash
python manage.py download_webdrivers
python manage.py load_component_pack
```

## 七、当日其他工程改动摘要（非鉴权项）

- 强制 headless、SSRF 校验

- H.264 Channels 队列背压；pkill 限定 testhub server jar  
- 手势使用 runtime driver；异步绑元素加锁  

### 7.3 其它

- 扫描 upsert 不抢手动分组  
- UI 录制密码脱敏  
- Channels 降级告警增强；Redis 默认 URL 去掉写死密码

## 九、常见问题

**Q: APP 投屏不更新？**  
用 Daphne + Redis≥5；检查 Nginx `/ws/`；看启动日志是否 InMemory。

**Q: Web 录制和投屏要不要两个后端？**  
不要。单 Daphne 即可同时服务。

**Q: 扫描提示繁忙 / 不允许内网？**  
并发槽占满；或触发了 SSRF 防护。

**Q: 8000 address already in use？**  
同时开了 runserver 与 daphne，只保留一个。
